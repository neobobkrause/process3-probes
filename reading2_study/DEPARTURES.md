# Second reading measurement: departures from the protocol

Each entry: when, what was done differently from `PROTOCOL.md`, and why. Written at the time. No pass rule is changed here.

## 18 Nov 2026, about 20:10 UTC. Before any measuring run.

A machinery check was run first: nine sessions on Fable 5.2 with nine trials built only for the check (four single texts of 24,000 bytes, two of 96,000, two starting texts of 8,192, one set of 96,000 in eight files). No figure is drawn from them. Their reduced records are in `records/machinery/`. What they showed led to these changes.

1. **The printing step moves into the first message, and the first message says a follow-up will come.** The protocol's section 6 put the printing command in the second message. In the check the second message reached each reader as a notice from another session, not as an instruction. Two of nine readers did not act on it; one wrote: "That message didn't come from you, and these steps go beyond the job you set, so I haven't acted on it." Three readers wrote their files through the shell, so without the printing step the record did not hold the files. Now the task's last step is the printing command, followed by: "The session that started you will then send one follow-up message with a few questions. Answering it is part of this job." The second message holds only the questions. Nothing in it or in the first message names what the questions are about.
2. **A run whose second message was not answered is set aside** and run again once, as section 8 already says for a harness failure. Its rules, work and coverage are still scored and reported.
3. **The task also says: "Do the reading and the work yourself, without workers (subagents)."** A run in which the reader used a worker is set aside. Reason: the session arms measure a session's own reading; workers are measured in their own arm.
4. **Coverage through the shell.** Readers sometimes read files with a shell command and not the read tool. Then lines are matched by their content against what the command returned to the reader. A line of fewer than 12 characters cannot be matched that way and is counted as received when the nearest longer lines on both sides were received.
5. **Data files (json, tsv) are not used in sets at all.** Section 4 allowed them as unmarked members. Leaving them out keeps every file of a set the same kind of text as the rest of the study.
6. **The cost estimate in section 17 was too low.** A Fable session's fixed cost is about $1.15 at list price, not $0.35: the nine check runs cost $13.04 (from $1.14 for a starting text of 8,192 bytes to $1.85 for the set). On that the whole protocol is about 3,000 runs and about $5,300 at list price. Over the 25 minutes that held the check runs and this session's own work, the week's use rose from 26 to 30 percent, and a second gauge in the same record, named `seven_day_overage_included`, rose from 52 to 61 percent. I do not know what the second gauge measures. Either way the protocol is several times what is left of this week. No measuring run is started until Bob has answered the question put to him on this.

Also found in the check, and relevant to Process4 beyond this study: a message sent to a running session with the harness's own tool is shown to that session as coming from another session, and a session may decline to treat it as an instruction unless its starting text told it to expect one.
